# 阶段五 · UI 改造计划

本阶段围绕三个日常动作改造工作台：找到课件、边读边记、确认笔记已经保存。采用 **Ant Design 通用控件 + 项目自己的阅读布局**。保留现有 PDF.js 渲染、目录拖拽、逐页草稿、版本冲突处理和三种工作模式。阶段五以 Safari、Chromium 人工交互验收为完成条件。

正式计划单独保存为 `docs/step5-PLAN.md`，保留你的手写草稿 `docs/step5-draft-plan.md`。以下将草稿要求、讨论确认的补充项和未来候选分开记录。

## 一、组件与视觉方案

- **引入 Ant Design。** 用于 Modal、定制下拉框、Tooltip、Popconfirm、Toast、Alert 和抽屉。通过统一主题配置让浮层跟随明暗模式。目录树继续使用现有拖拽实现，PDF、Markdown、笔记面板和模式切换保留专用布局。依赖加入前端项目及锁文件，记录引入前后的生产构建体积。[Ant Design 官方仓库](https://github.com/ant-design/ant-design) · [官方主题文档](https://ant.design/docs/react/customize-theme/)
- **以阅读内容为视觉中心。** 沿用现有蓝色作为选中、焦点和主操作色。浅色以白色内容面和灰蓝工作区分层；深色以蓝灰背景 `#1B2028`、面板 `#242B35`、正文 `#E2E7EE` 为起点。PDF 保留原始页面颜色，仅调整外围衬底。Markdown 正文、代码高亮、表格、输入框、浮层和全屏状态一并适配。
- **动效跟随操作。** 点击波纹从指针位置发起，键盘触发时从控件中央发起。侧栏、折叠、下拉和弹窗采用短过渡；拖拽反馈与实际落点一致。系统开启“减少动态效果”时取消位移、缩放和波纹，保留焦点、选中与结果反馈。

## 二、手写草稿要求及确认的实施方式

| 区域 | 实施决定 |
|---|---|
| 侧边栏 | 蓝色标记改为 **P**。移除排序说明、“固定”、“可拖入此处”和本机保存说明。桌面可拖右边缘调宽并记住宽度，菜单键控制滑动收展。课程最右侧常驻 **＋**，上方深色 Tooltip 提示“添加章节”；移序、删除保留在旁边的 **⋯**，悬停或键盘聚焦时显示，触屏常显。 |
| 目录编辑 | 课程／章节的展开箭头、拖动手柄和名称分别响应操作，扩大前两者的命中区域。可编辑名称悬停显示轮廓，单击后全选，Enter 或失焦提交，Esc 撤销，校验失败保留输入。系统“未分类”继续受保护；复习模式可展开目录、打开课件。课件名称仍用于打开文件，重命名从菜单进入网页弹窗。 |
| PDF 导入 | 导入弹窗、下拉列表和文件拖入分别提供打开／关闭、展开／收起、拖入／离开的反馈。课程与章节下拉末项内嵌创建输入框和“创建”按钮，按草稿文案提示；创建成功自动选中，失败保留输入。空文件区显示导入图标、“选择PDF文件”和“目前仅支持PDF格式课件，大小上限为100MB”。选中后显示红色描边 PDF 图标、粗体文件名、KB／MB 大小及文件本地修改时间。保留从工作区拖入、上传校验和错误后重选流程。 |
| 顶栏与全屏 | 三种模式以文字呈现，当前模式使用蓝色底线，支持悬停和点击波纹。全屏图标放在模式切换左侧，与实际浏览器全屏状态同步；Esc 退出和浏览器拒绝全屏时都给出正确状态，阅读位置与布局继续保留。 |
| 保存状态与日志 | 顶栏按真实保存结果显示，例如绿点加“14:53:20 已自动保存”，时间取成功响应时刻。区分等待 800ms、请求进行中、手动保存、失败和冲突；其他页仍失败时，单次成功不能把全局状态改成绿色。首次打开且尚无保存记录时显示“暂无保存记录”。悬停、聚焦或点按可在下方打开日志，按时间倒序显示**本次打开期间全部课件最近五条笔记、总结或问答保存结果**，附课件名与原始页码。分隔线下保留自动保存及快捷键说明。 |
| 课件标题与工具栏 | 标题左侧复用 PDF 图标，右侧显示“XX页”标签，删除标题下方重复说明。常驻**原始页码跳转**和**筛选入口**，入口摘要显示当前生效条件；分类和“显示隐藏页”收入筛选面板。“批量操作”单独打开，集中填写原始页码范围、分类和显示状态。复习模式仅展示可用的阅读操作。阶段日志单列一节，说明原两行工具如何重新分组，以及各功能的新入口。 |
| 编辑与复习 | 折叠标题使用轻底色、展开箭头和统一字号，与正文 Markdown 标题形成清晰层级。展开／收起加入波纹和高度过渡。编辑区重复标签替换为“可粘贴 AI 总结”“在这里写下你的笔记”，文本框提示为“支持Markdown样式”，保留可访问名称。复习模式问答按内容自然增高，一句话只占所需高度。编辑模式的垃圾桶在悬停时显示“确定删除本问答？”，键盘及触屏也可打开，明确确认后执行。 |
| 系统设置 | 在原清空入口放置“系统设置”。打开时检测后端，支持手动刷新，以状态点和文字呈现检测中、在线或连接失败。显示模式提供浅色、深色、跟随系统，首次默认跟随系统，在本机记住选择。清空全部数据使用二次 Modal，列明删除范围。底部按本地时间展示前端构建时间与后端启动时间，精确到秒。 |
| 系统反馈 | 普通操作结果从顶部滑入 Toast，含图标、正文和关闭键；成功默认 4 秒消失，失败手动关闭。后端断联、保存冲突等需要恢复操作的错误进入顶栏下方的持续 Alert，同一故障合并提示。断联提供“重试”，实际恢复后解除；冲突提供“查看冲突”，切至目标课件整理模式，临时显示被筛掉、隐藏或折叠的原页并展开对应字段。用户可比较版本、明确选择，再返回原课件、模式、筛选和位置。 |
| 浏览器弹窗 | 将应用主动调用的 `alert`、`confirm`、`prompt` 全部迁至网页内，包括目录操作、课件删除、清空、问答删除、草稿丢弃与冲突覆盖。按讨论结果，**刷新或关闭标签页时保留浏览器的未保存离页保护**。 |

## 三、补充项与未来候选

- **代码检查发现、你已确认纳入：窄屏目录与保存状态。** 现有窄屏布局会让目录挤占阅读宽度，并隐藏顶栏保存提示。改为窄屏默认收起目录，点击后以抽屉覆盖打开；顶栏保留可点按、带可访问名称的状态图标，点开可看完整状态和日志。
- **总计划要求、你已确认具体行为：课件与笔记分隔线。** 宽屏拖动任意页分隔线，全局同步调整两栏比例并在本机记住；同时支持键盘调节。窄屏自动改为上下排列，再次进入宽屏恢复比例。调整时保持当前页和编辑焦点，检查 PDF 画布与文字选择层对齐。
- **未来候选：整体采用 Ant Design 外观。** 加入 `PLAN.md` 的后续版本列表。待本阶段通用控件在真实学习流程中使用后，再决定是否统一替换目录、工作台与阅读面板的整体外观。

## 四、实施顺序与验收

1. **先做主题和运行信息。** 建立统一主题、浮层挂载位置及减少动态效果策略。Vite 在构建时注入时间；后端新增只读 `GET /api/status`，成功返回 `status` 和带时区的 `started_at`，启动时间在后端启动时确定。设置面板在检测失败时仍能打开并刷新。预计无需数据库迁移。
2. **再做目录、导入和阅读布局。** 依次完成目录行内编辑与调宽、导入与转移弹窗、顶栏与工具栏、双栏分隔线、笔记折叠及问答布局。保留长名称、空目录、只读、拖拽取消和请求失败状态。切换主题、调整宽度、打开浮层时保留页码、草稿及进行中的保存请求。
3. **最后接入保存反馈和恢复路径。** 从现有草稿保存流程采集真实结果；覆盖跨课件、并发成功／失败、手动重试及冲突跳转。Toast、Alert、日志分别承担操作回执、故障恢复和历史查看，避免同一错误反复弹出。
4. **自动验证。** 运行前端 Vitest、TypeScript／Vite 生产构建和后端 pytest。重点补测下拉内创建、行内重命名取消、只读限制、主题持久化、最近五条日志、同一时间跨页成功与失败、隐藏页冲突跳转与返回、运行状态接口和离页保护。检查应用源码中主动原生弹窗调用是否清零。

人工交互按各小节验收，撤销独立 5.5。5.4 后根据 Ant Design 使用清单另行决定整体外观。
