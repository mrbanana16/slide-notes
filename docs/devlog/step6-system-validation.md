## 改进建议

- **强化保存状态的可读性。** 600 px 窗口的保存入口在未打开浮层时只显示色点；建议为失败、冲突与待保存补充可见文字或可区分图标，并保留点击和键盘打开历史的方式。
- **控制目录和复习空状态的密度。** 320 px 目录里多个真实 lecture 文件名会换成三至四行，长课程名占用更大。可限制目录标题默认行数，并保留查看完整名称的方式。复习空白页上，区标题与正文重复显示「暂无内容」，可减少重复占位和留白。现有宽屏两栏、浅深背景和主操作层级清楚，可延续这套布局。
- **统一运行说明中的保存与只读语义。** README 和页面清单仍有可点击保存／重试按钮的说明，与当前交互有出入。PLAN 测试重点仍写复习不能持久化页面属性，而阶段 5.5 已确定三种模式均可折叠保存。待确认 S6-01 的恢复交互后，一并同步说明。[README](../../README.md) · [前端页面清单](../frontend-pages.md) · [阶段 5.5 日志](step5-ui-redesign.md)
- **补测前端加载成本。** 可在冷启动、目录变长、连续滚动和长笔记编辑下记录首屏时间、长任务及内存，结合构建体积提示决定是否拆分首屏资源。
