现在开始进行阶段五（前端设计专项优化）。本文件是我亲自起草的改造要求，你阅读后针对具体实施中的各类问题向我提问，最后生成一份针对本阶段的“UI改造计划”。

# 1.侧边栏

- 鼠标放置在右侧边缘时，允许拖动鼠标左右调节边栏大小。

- 将蓝色图标中的“页”修改为字母P。

- 删除调节顺序和确认移动的那行提示语。

- 删除未分类右侧的“固定”。

- 将课程右侧...中的“添加章节”移到...图标的位置显示，更换为+图标并在鼠标移到其上时使用Tooltip提示（含深色背景、浅色字体，显示与隐藏过渡动画且浮动在按钮上方的按键提示弹窗）。

- “重命名”功能取消在...的弹出菜单中显示，改为在鼠标移动到课程或章节名称时，显示文本框轮廓，点击名称后自动进入名称编辑（同时要自动选中全部文字）。注意，为防止误触重命名，名称左侧的展开/收起箭头和调整顺序滑块大小需要稍微扩大。

- 删除“暂无课件 · 可拖入此处”的·可拖入此处

- 删除“课件与笔记保存在本机”文字

- 点击标题左侧三条杠进行侧边栏隐藏/显示时，添加滑动动画

# 2.导入PDF弹窗

- 重构“导入课件”弹窗，在打开和关闭弹窗、点击下拉框、拖动PDF文件到弹窗内时引入弹出、关闭、放大、缩小等过渡和交互动画

- 下拉选择框不要使用系统样式，改为使用网页定制，配备展开收起动画

- 删除旧“创建课程”文本框和按钮，将“创建课程”与课程选择下拉框融合，即在课程下拉框的最后一项显示一个文本框，内部提示“也可在这里创建新课程...”，右侧配以按钮“创建”。章节下拉框按同样方式融合。

- 修改现有的导入课件后只显示纯文本文件名的样式。导入课件后，在上传文件区左侧显示红色的描边PDF图标，图标右侧显示文件名（粗体），文件名下方显示文件大小（单位为KB或MB，不足1MB即显示KB）和文件修改时间，例如“3.05 MB · 2026-01-01 13:40 修改”

- 删除“最大 100 MB，也可先将 PDF 拖入工作区。”，改为在“选择PDF文件”下方用小字提示“目前仅支持PDF格式课件，大小上限为100MB”，并在选择PDF文件标题上方新增表示“导入”的图标

# 3.顶栏

- 对于右侧的三个模式切换按键，恢复为原先的使用蓝色底线显示当前模式，其他模式以纯文本形式显示（不以按钮样式显示）；另外，仿照安卓Material设计风格，在点击模式切换按钮时可根据鼠标指针位置播放点击动画，鼠标移动到模式之上时也有相应动画。

- 最右侧的保存提示进行重构：仿照在线文档的自动保存提示，保存成功时使用【· 当前时间 已自动保存】的格式显示。如【14:53:20 已自动保存】。（·不要使用文字符号，用绿色/橙色/红色的点状图案表示保存情况：保存成功/正在保存/保存失败）

- 鼠标移动到保存提示之上时，在下方显示白色提示弹窗。弹窗中，先以【· 保存时间 保存情况】的格式逐条显示最近5条保存日志，如【· 14:43:20 保存成功】，最后在弹窗底部隔一条分割线，将现有保存提示语“停止输入约 800ms 自动保存 也可使用 ⌘ / Ctrl + S手动保存”放在其中

# 4.课件浏览界面

- 原黑色粗体标题的左侧加以显示文件类型图标（在导入PDF弹窗提及过），删除标题下方的页数和整理提示，改为在标题右侧显示“XX页”（样式类似标签，加以边框和背景色）

- 将全局全屏按钮移动到顶栏模式切换的左边，并改为以全屏图标显示，而不是文字
- “分类筛选”、“显示隐藏页”、“跳转页码”、“批量页码操作”这些功能杂糅在两行按钮中，非常不美观且难以操作，这部分由你来进行优化，在开发日志中需要另立一点说明这两行操作按钮的优化情况

# 5.笔记编辑区/阅读区
- 展开/收起板块时，仿照Android material设计，在鼠标点击位置播放交互动画，以及板块展开/收起时的交互动画。

- 删除编辑区与上方粗体标题重复的“AI 总结”、“个人笔记”文字，将输入提示语移动到该位置，如
“可粘贴 AI 总结”、“在这里写下你的笔记”

- 文本框提示语改为“支持Markdown样式”

- 追问与AI解答板块中，问题与回答的显示区域应根据内容长短动态变化（复习模式中），而不是在很短一句话的情况下仍占用大量空间；“删除问答”按钮改为垃圾桶图标，鼠标移动到上方时弹出Popconfirm，询问“确定删除本问答？”
- 当前各板块标题样式（黑色粗体）易与markdown标题混淆，需要进行样式修改

# 系统整体

- 对整个界面引入深色模式适配（除课件显示），当设置中设置为深色模式或选择“适配系统”且系统处于深色模式时，将全局背景、字体等进行适配，且配以切换过渡动画。注意，深色模式下的背景不要设置成全黑，配色方案要遵守适合长时间阅读和学习的原则

- 将原显示在底栏下方的系统提示改为从页面顶部向下弹出的Toast，配以成功/失败图标，提示正文，以及关闭按钮。成功提示在一段时间后自动消失，失败提示不会自动消失，必须由用户手动关闭。

- 对于系统严重错误，如后端断联的Failed to fetch、保存时与已有数据产生冲突等，需在顶栏下方显示Alert，以浅红色背景、警告图标和红色字体提示用户错误，并引导用户进行修复（如后端错误提示用户检查后端运行情况并提供重试超链接，保存冲突提示用户跳转检查并提供超链接快速跳转到保存出错的页面）

- 在原清空全部数据按钮位置新增“系统设置”，以覆盖弹窗形式提供设置项：显示后端运行状态【在点击打开设置时检测，并提供刷新按钮供手动检测】，以不同颜色的圆点和文字说明后端运行状态；显示模式（浅色/深色/跟随系统）；清空全部数据按钮（点击后弹出Modal确认）；底部显示当前运行系统的前端build时间和后端启动时间（年月日 时分秒）

# 改造要求

- 全面废除基于JavaScript的浏览器自带弹窗（含确认弹窗、文本输入弹窗等），全部改为网页内操作（如Modal等样式）

- 本次前端设计优化设计非常多的改动，需要引入大批动画，且需复用很多前端组件，因此我希望引入一套成熟的UI设计语言/UI库。经过搜索，我发现ant-design比较适合本项目(https://github.com/ant-design/ant-design) ，需要你评估一下是否适合引入。

- 本次前端优化的原则为不影响系统核心功能的基础上，使系统变得美观易用，界面清爽易懂。
